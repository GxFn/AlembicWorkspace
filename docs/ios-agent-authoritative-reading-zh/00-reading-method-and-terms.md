# 阅读方法、整理边界与术语约定

更新日期：2026-07-27

## 1. 这些文档是什么

本目录保存的是 Objective-C、Swift 与 AI Agent 权威资料的**中文精读稿**。

每份精读稿会尽量忠实保留原文的：

- 作者试图回答的问题；
- 论证展开的先后关系；
- 关键概念之间的因果关系；
- 底层机制、工程取舍与结论；
- 作者使用的证据类型；
- 版本、实验范围与适用边界。

这些文档不是第三方文章的逐句全文翻译，也不能替代原文。需要确认作者措辞、代码、
图表、实验设置或上下文时，应通过每篇开头的原文链接回到原作。

## 2. 为什么不按句子逐一对应

技术文章中，逐句替换英文单词往往会损坏真正的意思。例如：

- Swift 的 `dispatch` 讨论的是一次调用如何确定最终实现，不等于普通意义上的
  “任务调度”；
- Objective-C 的 `message`、`method`、`selector` 与 `implementation` 是四个
  不同层次，不能全部翻成“方法”；
- Agent 文章里的 `state`、`memory`、`context` 和 `history` 也不是同一个容器。

因此，本目录优先保持**概念关系和论证结构**，而不是追求英文句式与中文句式逐句对齐。

## 3. 证据层级

阅读时按下面的层级判断一条结论有多强：

1. **语言或平台语义**：语言、ABI 或平台明确承诺的可观察行为。
2. **编译器 / Runtime 常见实现**：解释当前系统通常怎样完成语义，但不一定是永久
   兼容承诺。
3. **具体工具链的优化结果**：只证明某个版本、参数和边界下生成了什么代码。
4. **同行评审研究结果**：结论受模型、任务集、指标、运行环境和样本范围限制。
5. **生产系统复盘**：说明某个团队在其场景下怎样解决问题，不自动成为普遍定律。
6. **独立作者的综合判断**：适合建立直觉，但应回到一级资料交叉确认。
7. **立场或方法论文章**：价值在于提供决策问题和反例，不应当作事实规范。

精读稿会尽量明确原文属于哪一层。

## 4. Objective-C 术语

| 英文 | 本目录用语 | 含义 |
| --- | --- | --- |
| object | 对象 | 携带身份并关联到类信息的实例 |
| class object | 类对象 | 在运行时表示一个类的对象 |
| metaclass | 元类 | 描述类对象自身行为的类 |
| message | 消息 | 接收者与 selector 构成的运行时请求 |
| method | 方法 | 类对某个 selector 提供的行为 |
| selector | 选择子 / selector | 方法名字在 Runtime 中的标识 |
| implementation / IMP | 实现 / IMP | 真正可以执行的函数入口 |
| message dispatch | 消息派发 | Runtime 根据接收者与 selector 查找实现 |
| forwarding | 消息转发 | 正常查找失败后把处理机会交给其他对象或通用调用表示 |
| method swizzling | 方法交换 / Swizzling | 运行时改变 selector 与 IMP 的映射 |
| associated object | 关联对象 | 不改变实例布局而在旁路存储中附加关联值 |
| autorelease pool | 自动释放池 | 管理延后释放对象的作用域机制 |
| non-pointer `isa` | 非指针 `isa` | 在 `isa` 存储中编码类信息之外的状态位 |

首次出现容易混淆的术语时，会保留英文或 Runtime 名称。

## 5. Swift 术语

| 英文 | 本目录用语 | 含义 |
| --- | --- | --- |
| dispatch | 派发 | 一次调用最终执行哪段实现以及如何到达它 |
| static/direct dispatch | 静态 / 直接派发 | 调用目标可以直接绑定，不需要运行时多态选择 |
| virtual dispatch | 虚派发 | 根据对象的动态类类型选择 override 实现 |
| protocol witness | 协议见证 | 某个具体类型满足协议要求的实现证据 |
| witness table | 协议见证表 | 表示某个具体 conformance 的实现入口集合 |
| existential | 存在类型 / 存在值 | 隐藏具体类型、只保留协议能力的包装 |
| opaque type | 不透明类型 | 隐藏但保持为同一个具体类型的抽象结果 |
| specialization | 特化 | 针对具体类型生成或优化实现 |
| devirtualization | 去虚化 | 把原本需要间接选择的调用优化成已确定目标的调用 |
| value semantics | 值语义 | 值之间表现为相互独立，而不是共享可观察身份 |
| identity | 身份 | 即使内容相同仍可区分为不同对象的性质 |
| copy-on-write | 写时复制 / COW | 共享存储直到一方将要修改的优化策略 |
| ownership | 所有权 | 值由谁保持、借用、转移和销毁的规则 |
| borrowing | 借用 | 临时使用值而不取得其所有权 |
| consuming | 消费 | 使用并转移或结束当前所有权 |
| resilience | 演进韧性 / resilience | 二进制组件在未来改变实现或布局仍保持兼容的能力 |
| actor isolation | Actor 隔离 | 对受保护状态的静态访问边界 |
| executor | 执行器 | Swift Concurrency 用来安排可运行任务片段的抽象 |

不能把某个类型永久贴上唯一派发标签。派发要结合调用表达式、静态类型、声明种类、
模块边界、conformance、语言语义和优化结果判断。

## 6. AI Agent 术语

| 英文 | 本目录用语 | 含义 |
| --- | --- | --- |
| agent | Agent | 能根据状态与反馈动态选择后续行动的 AI 系统 |
| workflow | 工作流 | 主要由预先写好的代码路径决定执行步骤的系统 |
| compound AI system | 复合 AI 系统 | 模型、检索、工具、验证器和控制逻辑共同组成的系统 |
| harness | Agent 执行框架 / harness | 包围模型并管理循环、工具、状态、权限和恢复的确定性软件 |
| tool | 工具 | Agent 能够请求执行的受约束外部能力 |
| trajectory / trace | 执行轨迹 | 模型决策、工具调用、结果和状态变化形成的完整序列 |
| context | 上下文 | 当前模型调用实际可以看到的信息 |
| memory | 记忆 | 跨步骤或跨会话保存并可再次取回的信息 |
| state | 状态 | 系统当前真实进展、环境内容和控制信息 |
| context engineering | 上下文工程 | 选择、组织、压缩、隔离和更新模型可见信息 |
| orchestrator-worker | 编排者—工作者 | 中央角色分解任务并协调多个工作单元的结构 |
| evaluator-optimizer | 评估者—优化者 | 生成结果后反复评价和改进的控制结构 |
| eval | 评测 | 对系统在一组任务上的行为进行可重复测量 |
| grader | 评分器 | 根据规则、代码、模型或人工判断一次试验结果 |
| outcome | 最终结果 / 环境状态 | 任务结束时真实世界或测试环境发生了什么 |
| prompt injection | 提示注入 | 不可信内容试图改变 Agent 的控制目标或行为 |
| least privilege | 最小权限 | 只授予完成当前动作所必需的能力和数据访问 |

本目录继续使用用户熟悉的 “Agent”，不强制全部替换成“智能体”。

## 7. 精读稿的统一结构

每篇通常包含：

1. 来源信息；
2. 文章要解决的问题；
3. 原文论证主线；
4. 关键机制与结论；
5. 证据、准确性或版本边界；
6. 在整套知识体系中的位置。

长篇专著和论文只建立结构化导航，不会用一篇中文笔记替代几百页原作。
