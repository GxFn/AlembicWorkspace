# 在 Swift 中使用非复制类型

- **Original title**: Consume noncopyable types in Swift
- **原文链接**: [Apple Developer](https://developer.apple.com/videos/play/wwdc2024/10170/)
- **作者/机构**: Kavon Farvardin / Apple Swift 团队
- **年份**: 2024
- **材料类型**: WWDC 所有权演讲、示例代码与文字稿
- **文档性质**: 忠实中文精读，不是原文全文翻译

## 文章要解决的问题

普通 Swift 值可以被赋值、传参和返回，语义上都允许形成独立副本。对于锁、文件描述符、事务令牌或必须唯一持有的资源，复制不是昂贵而已，而是没有正确含义。原文介绍如何在类型系统中声明不可复制，并让函数明确表达只是借用还是会消费该值。

## 原文论证主线

演讲先澄清两种复制：复制 class 值只复制引用，多个变量仍指向同一对象；复制具有值语义的容器则要求随后修改彼此独立，底层可用 COW 实现。接着引入默认的 `Copyable` 能力和 `~Copyable` 抑制约束。非复制值在移动或被消费后，原绑定不能再次使用；只读观察可通过 borrowing 约定完成，不转移销毁责任。随后材料把规则扩展到泛型、协议和扩展。

## 关键机制与结论

`consuming` 表示被调用方取得值并负责其后续生命周期，适合完成、关闭或转移资源；`borrowing` 只在调用期间读取，来源继续拥有值。泛型默认往往仍假设可复制，只有显式允许 `~Copyable` 后才能同时接受两类值。非复制语义减少了错误状态，也可能省去 COW 唯一性检查和引用计数，但主要价值是让非法复制无法通过类型检查。

## 准确性与版本边界

非复制基础能力从 Swift 5.9 起逐步出现，Swift 6 扩展到更完整的泛型使用；实际支持组合仍随 6.x 演进。禁止的是源码语义上的复制，不代表机器码不能移动字节、使用临时寄存器或被优化重排。反过来，声明 `~Copyable` 也不保证没有堆分配或引用计数，因为类型内部仍可能持有引用资源。具体标准库采用范围和部署可用性需按工具链核验。

## 在知识体系中的位置

它是 Ownership Manifesto 的现代落地入口，将抽象的共享、借用和消费变成可写接口。之后阅读 Swift 6.2 的 `Span`、非逃逸类型和值泛型，可以看到相同所有权信息如何保护借用内存并支持低层性能代码。
