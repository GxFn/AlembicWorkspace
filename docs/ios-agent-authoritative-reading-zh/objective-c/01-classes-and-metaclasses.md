## 文章要解决的问题

Objective-C 里“类也是对象”常被当成一句口号，却没有回答三个紧接着的问题：实例方法和类方法分别存在哪里；向类发送消息时由谁负责查找；如果类本身也是对象，它又是谁的实例。原文用两条关系链把这些问题统一起来。

## 原文论证主线

普通对象是某个类的实例。类描述这类实例的大小、实例变量布局和可响应的实例方法。向实例发送消息时，查找从它所属的类开始，再沿类的 superclass 链向上。

类本身也是可以接收消息的对象，因此也需要一个“描述它的类”，这就是元类。类方法并不是一种脱离对象模型的特殊函数，而是存放在元类方法列表中的实例方法：接收者恰好是类对象。向类发送 `alloc` 一类消息时，查找从该类对象所属的元类开始。

元类的 superclass 链大体平行于普通类的继承链，所以类方法也能继承。根元类的 superclass 指向根类，根元类的 `isa` 最终形成自环，避免出现无限层级的“元元类”。原文最后强调，理解图时要分开看两种边：`isa` 回答“它是谁的实例”，superclass 回答“找不到方法时去哪里继续找”。

## 关键机制与结论

对象、类对象和元类使用的是同一套消息模型。实例方法由类描述，类方法由元类描述；两者最终都是 selector 到实现的映射。所谓“调用类方法”，实质仍是给一个对象发送消息，只是这个对象代表一个类。面试中如果只说“类方法放在元类里”还不够，应能继续解释类对象为何需要元类，以及类方法继承为什么依赖元类的 superclass 链。

## 准确性 / 版本边界

文章写于 2009 年，把 `isa` 表述为直接指向类的指针，适合建立概念图，但现代 Runtime 可能使用 non-pointer `isa`，`Class` 的内部结构也是不透明实现。应用代码不应读取 `obj->isa`，应使用 `object_getClass`、`class_getSuperclass` 等公开入口。根类细节也可能随 Runtime 演进，稳定的是对象—类—元类的语义关系，而不是某版结构体字段。
