# 怎样评测真正有用的 AI Agent

- **Original title**：AI Agents That Matter
- **原文链接**：[arXiv 论文](https://arxiv.org/abs/2407.01502)
- **作者/机构**：Sayash Kapoor、Benedikt Stroebl、Zachary S. Siegel、Nitya Nadgir、Arvind Narayanan；Princeton University
- **年份**：2024
- **材料类型**：研究论文 / 评测方法批判
- **文档性质**：忠实中文精读，不是原文全文翻译。

## 文章要解决的问题

Agent 研究被 benchmark 排名推动，但只看准确率会奖励昂贵复杂系统，测试集污染与调参又可能制造虚假进步。论文追问：什么评测才能帮助下游开发者选择有实际价值、成本可接受且结果可复现的 Agent？

## 原文论证主线

作者提出四类缺陷。第一，只优化准确率而忽略成本，使额外模型调用带来的小幅收益被误解为架构突破；第二，基础模型评测与下游 Agent 选择混在一起，无法回答具体应用该部署什么；第三，缺少严谨留出集，开发者可能对公开任务过拟合，甚至利用环境漏洞；第四，报告协议不统一，模型版本、采样次数、工具和预算差异让结果难以复现。论文据此主张联合优化准确率与成本，并分离开发集、测试集和独立评测。

## 关键机制与结论

Agent 是模型与 scaffold 的组合，比较时必须固定或清楚报告二者。成本—准确率应画成前沿，而不是只公布最高点；更简单的 Agent 可能在同样准确率下便宜很多。下游评测应反映目标业务分布和约束，模型研究则需要控制 scaffold 以判断能力来自哪里。留出任务、限制调试访问、记录完整运行配置和多次试验，是避免 benchmark 过拟合的最低要求。

## 证据与适用边界

论文通过当时若干 Agent benchmark 与成本优化案例展示结论，重点是方法论诊断，不是覆盖所有任务的元分析。价格、模型和基准在 2024 年后快速变化，但成本、污染与可复现性问题不会因某个榜单更新而消失。它也未解决开放式质量如何完全客观评分，需要与结果状态检查、人工和模型 grader 结合。

## 在知识体系中的位置

这是阅读任何 Agent SOTA 数字前的“防误读层”。它迫使读者区分模型进步、harness 进步和测试集适配，并把成本、延迟、可靠性纳入完成定义。

## 精读时应保留的判断

比较 Agent 时要报告每个任务允许的模型调用、工具调用、并发、重试、上下文长度和人工介入，否则准确率不可解释。若新方案只靠更大预算超过旧方案，应在成本—质量前沿上呈现，而不是称为纯架构提升。公开 benchmark 可用于相对研究，部署选择还需用本地任务分布、权限与失败代价验证。留出集不能反复用于提示调参；一旦开发者看见案例，它就更接近训练材料而非独立测试。
