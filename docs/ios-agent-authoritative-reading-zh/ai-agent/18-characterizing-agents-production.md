# 生产环境中的 Agent 到底长什么样

- **Original title**：Characterizing Agents in Production
- **原文链接**：[IBM Research / ICML 2026](https://research.ibm.com/publications/characterizing-agents-in-production)
- **作者/机构**：Melissa Pan、Negar Arabzadeh 等；IBM Research、UC Berkeley 等
- **年份**：2026
- **材料类型**：同行评审实证研究
- **文档性质**：忠实中文精读，不是原文全文翻译。

## 文章要解决的问题

论文指出，学术论文和产品宣传常展示长链自治与复杂架构，却缺少一手生产数据。CAP 研究真实团队为何部署 Agent、实际采用哪些技术、如何评测，以及最大障碍是否与公开 benchmark 的关注点一致。

## 原文论证主线

研究采用混合方法：对 20 个生产案例做深度访谈，再调查来自 26 个领域的 306 名从业者。问题覆盖动机、模型适配、步骤长度、人工介入、评测方式和开发挑战。作者将这些经验与“完全自主、持续学习、复杂多 Agent”的主流叙事比较，发现生产选择通常更保守：流程短、可控、靠系统层约束，且人工仍是重要判断者。

## 关键机制与结论

68% 的受访部署在人工介入前最多执行 10 步；70% 主要通过提示使用现成模型，而非改模型权重；74% 的主要评测依赖人工。最突出的挑战是长期一致地正确，也就是可靠性，而团队主要通过权限、检查点、工作流设计、验证和人工监督等系统手段处理。论文因此主张研究议程应更关注可控短轨迹、真实工作条件和评测基础设施。

## 证据与适用边界

这是目前少见的大范围一手生产研究，但并不等于全行业普查。访谈和问卷存在自我报告、术语理解、样本选择与幸存者偏差；不同领域对“步骤”和“人工介入”的定义也可能不完全相同。数据刻画的是 2026 年当下状态，不证明短 Agent 永远最优，也不能据此忽略正在增长的长时自治能力。

## 在知识体系中的位置

CAP 是校正架构想象的重要基线。它把 Anthropic“从简单开始”、12-Factor 的可暂停控制和系统级可靠性放到经验数据中，也提醒评测研究不要只追逐一次性 benchmark 最高分。

## 精读时应保留的判断

不能从“68% 不超过十步”推出十一步就不应部署，正确理解是当前生产团队常用短回路控制可靠性。评审自己的系统时，应记录人工介入发生在何种风险与不确定性上、介入前已改变哪些状态、人工是否有足够证据判断。74% 依赖人工评测也不是理想终点，它反映自动 grader 与真实成功定义仍有缺口。后续方向应把专家判断逐步转化为可重复测试，同时保留无法自动化的质量维度。
