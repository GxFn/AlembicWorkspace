# 微软 Agentic AI 失败模式分类更新

- **Original title**：Updating the taxonomy of failure modes in agentic AI systems: What a year of red teaming taught us
- **原文链接**：[Microsoft Security Blog](https://www.microsoft.com/en-us/security/blog/2026/06/04/updating-taxonomy-failure-modes-agentic-ai-systems-year-red-teaming-taught-us/)
- **作者/机构**：Microsoft AI Red Team
- **年份**：2026
- **材料类型**：红队生产经验 / 安全 taxonomy 更新
- **文档性质**：忠实中文精读，不是原文全文翻译。

## 文章要解决的问题

微软 2025 年首版 taxonomy 主要来自威胁建模；经过十二个月对已部署 Agent 系统的红队工作，部分预测被确认、部分需重分，新攻击面也随着 MCP、计算机操作与多 Agent 落地而出现。文章解释为何要发布 v2。

## 原文论证主线

更新增加七类：Agent 供应链破坏、目标劫持、Agent 间信任升级、计算机操作 Agent 的视觉攻击、会话上下文污染、MCP/插件滥用、能力与架构泄露。运营观察显示，人工审批绕过、跨域提示注入和记忆投毒频繁出现；攻击者还可把许多单步看似低风险的动作串成高影响结果，或先探出工具 schema、审批触发条件，再设计后续路径。

## 关键机制与结论

文章建议把自然语言工具描述与提示模板纳入供应链清单和版本监控；Agent 身份用可验证凭证，而不是因其处于某个工作流位置就信任；审批应从底层工具调用生成动作摘要，按可逆性和爆炸半径分级，并以确定性规则触发；上下文需要来源标记、可信/不可信分区、跨会话完整性监控和边界。红队必须测试完整多步链，模型级单轮评测无法覆盖这些问题。

## 证据与适用边界

v2 明确基于十二个月真实 engagement，而不是纯理论，但文章没有公开客户数、攻击成功率分母、行业分布或完整原始案例，出于安全与保密也难独立复现。“高频”是团队观察，不应被转换成全行业发生率。某些具体生态数字和漏洞会快速变化，taxonomy 本身也被作者称为活文档。

## 在知识体系中的位置

它为 OWASP 横向清单增加了时间和攻击链视角，尤其突出供应链、会话污染、Agent 身份与审批疲劳。它说明安全问题位于模型、编排、工具、记忆、人机界面和外部生态的交界处。

## 精读时应保留的判断

审批存在不等于人工回路有效。审批内容若由可能已被劫持的 Agent 自行概括，攻击者可把高风险动作包装成低风险说明；更可靠的界面应从真实工具参数和权限变化生成摘要，并让用户看到对象、范围、可逆性与替代方案。跨 Agent 消息也不能因来自“内部 Agent”就提升信任，身份、权限和数据来源要独立验证。会话级攻击要求把多步小变化作为整体观察，单轮分类器很难发现渐进升级。
