# 构建 Manus 得到的上下文工程经验

- **Original title**：Context Engineering for AI Agents: Lessons from Building Manus
- **原文链接**：[Manus 原文](https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus)
- **作者/机构**：Yichao “Peak” Ji；Manus
- **年份**：2025
- **材料类型**：厂商生产复盘 / 工程立场文章
- **文档性质**：忠实中文精读，不是原文全文翻译。

## 文章要解决的问题

Manus 团队选择在前沿模型之上做上下文工程，而不是先训练端到端 Agent 模型。经历四次框架重写后，文章总结哪些看似细小的上下文决策实际影响延迟、成本、稳定性和长任务方向。

## 原文论证主线

全文围绕六条局部最优经验展开。第一，稳定提示前缀、采用只追加历史和确定性序列化，以提高 KV cache 命中；第二，工具可用性变化时尽量保留定义，通过 logits mask 等方式约束选择，避免破坏缓存；第三，把文件系统当作可恢复的外部上下文，工具输出过大时写文件并留下引用；第四，持续重述待办计划，使目标靠近上下文尾部；第五，保留失败动作与错误观察，让模型看到哪条路不通；第六，适度改变重复模式，减少 Agent 机械模仿历史轨迹。

## 关键机制与结论

文章把上下文视作 Agent 运行时的主要状态与计算预算。缓存友好的稳定前缀降低重复推理成本；文件并不是“自动记忆”，而是可由路径重新加载的外部状态；计划复述对抗目标在长轨迹中被稀释；错误记录承担负反馈，盲目删除失败会让模型重试同一路径。整体结论是，harness 如何构造每轮输入，往往与底层模型选择同样重要。

## 证据与适用边界

这些结论来自 Manus 大量会话和产品迭代，但文章没有公开任务分布、对照实验、绝对成功率或失败样本比例，因而属于可信的厂商经验而非可复现定律。KV cache 和工具屏蔽策略依赖具体推理服务；保留错误或注入变化也可能浪费 token、引入噪声，必须在自己的模型与任务上评测。

## 在知识体系中的位置

它是 Anthropic 上下文原则的具体生产补充，尤其适合理解缓存、外部文件、计划位置和失败轨迹这些运行细节。阅读时应把“我们在 Manus 有效”与“所有 Agent 都应如此”严格分开。

## 精读时应保留的判断

六条技巧服务的目标并不相同：缓存优化成本与延迟，文件外置扩展可恢复状态，计划复述维持方向，错误轨迹帮助避免重复。落地时应分别设置指标，不能看到总成功率变化便猜是哪条生效。把大结果写入文件还需保证文件可定位、未被篡改、权限正确且能按需读取；保留失败也要压缩无关日志。任何“受控噪声”策略都可能破坏可重复性，必须有留出任务和多次试验。
