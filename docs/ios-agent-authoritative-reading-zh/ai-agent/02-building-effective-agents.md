# 构建有效的 AI Agent

- **Original title**：Building Effective AI Agents
- **原文链接**：[Anthropic 原文](https://www.anthropic.com/engineering/building-effective-agents)
- **作者/机构**：Erik Schluntz、Barry Zhang；Anthropic
- **年份**：2024
- **材料类型**：厂商工程经验 / 架构模式总结
- **文档性质**：忠实中文精读，不是原文全文翻译。

## 文章要解决的问题

“Agent”常被用来指完全自治系统，也常被用来包装固定流程。文章试图建立一套可操作的区分：什么时候只需一次模型调用，什么时候用确定性工作流，什么时候才值得让模型动态决定步骤，并给出逐级增加复杂度的常见模式。

## 原文论证主线

作者先区分 workflow 与 agent：工作流由代码预先规定路径，Agent 则由模型动态决定过程和工具使用。基础构件是带检索、工具和记忆的增强型 LLM；其上依次可以构造提示链、路由、并行化、编排者—工作者、生成者—评估者等工作流。只有当问题开放、步骤数量无法预先确定且需要根据环境反馈调整时，才进入自主循环。全文反复强调先采用最简单可行方案，再以评测证明增加复杂度确有收益。

## 关键机制与结论

固定可分解任务适合提示链；输入类别清晰时适合路由；独立子问题或多视角检查适合并行；子任务只能运行时发现时可用编排者—工作者；有明确质量标准且反馈能改善结果时可用评估—优化循环。真正的 Agent 通常只是模型在“观察环境—选择工具—读取结果—修正方向”循环中工作，并设置停止条件、检查点和人工介入，而不是庞大的专用框架。

## 证据与适用边界

文章来自 Anthropic 与数十个客户团队及自身产品的经验，包含编码和 computer-use 示例，但没有公开统一样本、对照组或完整成本数据。因此“成功团队偏好简单组合模式”是有价值的生产观察，不是跨模型、跨行业的统计定律。其术语也是 Anthropic 的分类方式；其他资料可能把部分动态工作流也叫 Agent。

## 在知识体系中的位置

它提供本资料集的基础架构词汇，并能防止把“静态流程”和“模型动态派发”混写。阅读后应能回答：某能力究竟需要一次调用、确定性编排，还是需要 Agent 自主性；复杂度的增加应由哪类任务特征和哪项评测结果来证明。

## 精读时应保留的判断

真正的架构选择题不是“要不要 Agent”，而是控制权在哪些节点交给模型。可预先枚举且后果明确的步骤尽量由代码控制；只有路径依赖环境反馈、分支无法穷举时，动态决策才提供独特价值。即便采用 Agent，也应保留最大轮数、预算、终止条件、人工检查点和可回滚动作。面试回答若只背五种模式而不说明适用条件，仍没有完成工程判断。
