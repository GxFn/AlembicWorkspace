# 面向 AI Agent 的有效上下文工程

- **Original title**：Effective context engineering for AI agents
- **原文链接**：[Anthropic 原文](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)
- **作者/机构**：Anthropic
- **年份**：2025
- **材料类型**：厂商工程方法 / 深度技术文章
- **文档性质**：忠实中文精读，不是原文全文翻译。

## 文章要解决的问题

Agent 每轮都可能产生新消息、工具结果、文件和计划，问题早已不只是“系统提示怎么写”，而是有限上下文窗口中此刻应该放什么、删什么、压缩什么、按需取什么。文章为这种动态选择建立工程原则。

## 原文论证主线

作者把上下文定义为一次推理时模型可见的全部 token，包括系统指令、工具定义、示例、消息历史和外部数据。随着长度增长，模型并非到某个阈值突然失效，而是注意力精度逐渐下降，因此目标应是用尽可能少的高信号 token 触发期望行为。文章依次讨论合适“高度”的指令、边界清晰的最小工具集、少而典型的示例、运行时按需检索，以及长轨迹中的压缩、结构化笔记和子 Agent 隔离。

## 关键机制与结论

上下文工程是每一轮都发生的选择过程。与预先把所有资料塞入提示相比，“just in time”策略只保留文件路径、链接、查询等轻量索引，由 Agent 用工具在需要时加载原文。压缩用于保留决策、未完成事项和关键证据；外部记忆让大对象留在文件或数据库中；子 Agent 可用独立窗口完成高 token 调研，只把高密度结果返回。结论不是“越短越好”，而是完整表达任务所需信息的最小高信号集合。

## 证据与适用边界

文章结合 Claude Code、Anthropic 客户和既有长上下文研究总结实践，并引用“context rot”类实验说明长上下文的边际收益递减；它没有给出跨所有模型的统一最优压缩率或检索阈值。文件系统、MCP 和特定模型的经验不能原样套到高监管记忆系统；摘要会丢信息，按需检索也可能漏召回，均需用任务评测和来源记录校验。

## 在知识体系中的位置

这是连接提示工程、工具设计和记忆系统的中枢文章。它纠正两个常见误解：上下文窗口大不等于可靠记忆，把所有可能相关内容都提供给模型也不等于信息更充分。

## 精读时应保留的判断

上下文选择本身是一项会失败的检索与压缩程序，应像其他组件一样记录和评测。对每轮输入，最好能回答某段信息来自哪里、为何被选中、是否过期、是否可信、删去后会发生什么。摘要必须链接可回查原证据，长期状态与临时观察要分层，不可信网页内容不能与系统规则混成同一权限级别。模型窗口升级后仍需做位置和长度扰动，因为容量增加不自动消除注意力竞争。
