# 从环境、工具与规划理解 Agent

- **Original title**：Agents
- **原文链接**：[Chip Huyen 原文](https://huyenchip.com/2025/01/07/agents.html)
- **作者/机构**：Chip Huyen
- **年份**：2025
- **材料类型**：工程教材章节改编 / 深度综述
- **文档性质**：忠实中文精读，不是原文全文翻译。

## 文章要解决的问题

文章不从某个框架出发，而是追问 Agent 的能力从哪里来、为什么会失败。它把经典 AI 中“感知环境并对环境行动”的定义带回当前大模型系统，再重点拆解工具库存、规划、反思与评测之间的关系。

## 原文论证主线

Agent 由其环境和可执行动作刻画；在大模型 Agent 中，模型充当根据目标和约束作出计划的“脑”，工具负责感知或改变环境。工具可分为知识增强、能力扩展和写入环境的动作。复杂任务需要在候选方案、步骤粒度、工具约束和成本之间规划，执行结果又反过来修正计划。随着步数增加，规划错误、工具选择错误、参数错误、环境故障和“误以为已经完成”会叠加，因此评测必须从具体失败模式出发。

## 关键机制与结论

文章建议在高代价任务中分开计划与执行：先生成并验证计划，排除不存在的工具、过长路径或不满足约束的方案，再执行并根据反馈重规划。工具数量增加会扩大能力，也会增加选择难度；读操作和写操作的风险并不相同。评测不仅问最终是否完成，还要统计有效计划率、错误工具与参数、平均步骤、耗时和成本。其中心结论是：Agent 表现取决于规划器、工具接口和环境反馈的组合，而非模型榜单分数。

## 证据与适用边界

本文综合大量早期论文、产品与示例，部分内容来自作者 2025 年《AI Engineering》一书，不是一项单独实验。文中用“单步 95% 准确率在多步后下降”说明误差复合，这是独立同分布假设下的示意计算，不应当作真实 Agent 的可靠性曲线。作者把一些 RAG 系统也纳入广义 Agent，口径比“模型在循环中自主用工具”的定义更宽。

## 在知识体系中的位置

这篇适合连接经典 Agent 概念与现代 LLM 工程：它解释了“环境、动作空间、规划器”这些面试高频词，也自然引出 ReAct、工具设计、上下文管理和基于失败模式的评测。

## 精读时应保留的判断

定义 Agent 时最好明确采用哪个口径，并说明自主性程度，而不要争论某个 RAG 是否“算 Agent”。更有用的描述是：它能观察哪些环境状态、可调用哪些读写动作、由谁决定下一步、怎样判断完成、失败后能否恢复。规划也不应被神化为一次生成完整步骤；现实系统往往滚动规划，只承诺下一小段可验证动作，并在工具观察后更新。高风险写操作还需与只读探索分权。
