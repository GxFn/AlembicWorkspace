# Swift：类型系统、内存语义与派发

> 知识树定位：B3 Swift、B4 混编与迁移；并发类型安全继续见 C4 Swift Concurrency。

## 1. 值类型与引用类型

### 1.1 语义优先

- `struct`、`enum` 是值类型，赋值和传参表达独立值语义；
- `class` 是引用类型，多个变量可以指向同一实例；
- “值类型一定在栈、引用类型一定在堆”是错误简化，编译器会逃逸分析、内联和优化；
- 选型应先看身份、共享可变状态、继承、生命周期和复制语义。

适合值类型：

- 配置、坐标、不可变业务快照；
- 希望本地推理、减少共享状态；
- 可自然表达 `Equatable` / `Hashable`。

适合引用类型：

- 对象身份本身有意义；
- 多方需要观察同一可变状态；
- 生命周期和资源管理需要集中；
- 与 Objective-C / UIKit 类体系互操作。

### 1.2 Copy-on-Write

Swift 标准集合常通过 Copy-on-Write 优化复制：多个值可以暂时共享底层存储，写入前检测唯一性并复制。它保留值语义，但不代表“复制永远零成本”。

自定义 COW 需要：

- 私有引用存储；
- 修改前使用唯一性检查；
- 不泄漏可变底层引用；
- 用基准和内存工具验证是否值得复杂度。

## 2. Optional 与错误处理

Optional 表示值可能缺失，是类型系统的一部分，不只是语法糖。常见策略：

- `if let` / `guard let`：控制分支；
- `map` / `flatMap`：变换可选值；
- `??`：提供语义合理的默认值；
- `!`：仅在不变量已由其他机制保证时使用。

错误模型：

| 机制 | 用途 |
| --- | --- |
| `throws` | 调用方可以恢复或向上传播的失败 |
| Optional | 只关心“有/无”，不需要失败细节 |
| `Result` | 需要把异步/存储的成功或失败作为值传递 |
| assertion/precondition | 开发期或调用合同被破坏 |
| fatal error | 确实无法继续的程序不变量破坏 |

不要用崩溃代替正常业务错误，也不要把所有失败压扁成 `nil`。

## 3. ARC 与闭包捕获

Swift 的 ARC 只管理类实例的引用生命周期。结构体如果持有类引用，复制结构体仍可能共享其中的类实例。

闭包捕获要分析：

- 捕获值还是捕获存储；
- 逃逸闭包会活多久；
- owner 是否持有闭包；
- 闭包是否必须持有 owner；
- 异步任务是否支持取消。

```swift
final class Loader {
    var onFinish: (() -> Void)?

    func bind() {
        onFinish = { [weak self] in
            guard let self else { return }
            self.consumeResult()
        }
    }
}
```

`unowned` 适合被捕获对象在闭包执行时必然存活的强不变量；判断错误会导致运行时崩溃。

## 4. Protocol、Generic、`any` 与 `some`

### 4.1 Protocol

Protocol 描述能力合同。Protocol Extension 可以提供默认实现，但要区分：

- 协议要求的方法通常通过 witness table 参与多态；
- 只在 extension 增加、未进入协议要求的同名方法，静态类型可能影响调用结果；
- 默认实现不是多继承，也不能隐藏状态所有权。

### 4.2 Generic

泛型让调用点选择具体类型，编译器可以进行特化和静态检查。代价可能是编译时间、代码体积和复杂的约束表达。

### 4.3 `some Protocol`

Opaque Type：

- API 隐藏具体类型；
- 实现方选择一个确定的底层类型；
- 调用方保留静态类型信息；
- 不等于“任意符合协议的类型”。

### 4.4 `any Protocol`

Existential：

- 可以装入运行时不同的符合类型；
- 通过容器/间接层实现动态多态；
- 可访问协议合同成员；
- 可能产生装箱、间接调用或能力限制。

答题核心：

> 泛型是调用方选择类型，opaque 是实现方选择一个隐藏的具体类型，existential 是运行时容纳任意符合类型。选型先看是否需要异构存储和动态替换，再看性能。

## 5. Associated Type 与类型擦除

带 associated type 或 `Self` 要求的协议更适合作为泛型约束。若需要异构集合、稳定模块边界或运行时替换，可以：

- 使用 `any` existential（当协议能力允许）；
- 设计显式类型擦除器；
- 把差异转化为 enum；
- 重新检查是否真的需要异构。

类型擦除不是免费魔法：它会增加包装、间接调用和调试成本。

## 6. 派发方式

Swift 可能使用：

- 静态派发：编译期确定，常见于值类型、泛型特化；
- vtable 派发：类继承和可重写方法；
- witness table：协议要求的实现分派；
- Objective-C 消息派发：`@objc dynamic` 或 OC 互操作边界；
- 内联/去虚化：优化器在证明安全时消除动态成本。

不要从源代码一个关键字推断 Release 二进制的最终机器行为；性能结论需要编译产物和测量支持。

## 7. 内存安全与独占访问

Swift 提供：

- 初始化前不可读；
- 数组边界检查；
- 生命周期安全；
- 独占访问检查；
- 并发模型中的数据竞争检查能力。

典型独占访问冲突来自：

- `inout` 参数执行期间再次访问原变量；
- `mutating` 方法中重入访问同一存储；
- 闭包捕获与长时间访问重叠。

```swift
func adjust(_ x: inout Int, using y: Int) {
    x += y
}
```

`inout` 表达对存储的一段读写访问，不应简单解释为“永远传地址”。

## 8. Collection 与复杂度

面试不仅要背 Big-O，还要说明输入分布和常数成本：

- `Array` 尾部追加通常摊销 O(1)，中间插入/删除 O(n)；
- `Dictionary` / `Set` 平均查找接近 O(1)，依赖良好 Hash；
- `String` 索引不是整数随机访问，因为 Unicode grapheme cluster；
- `lazy` 可以避免中间集合，但重复求值和捕获生命周期要考虑；
- `Sequence` 可能只能消费一次，`Collection` 提供多遍遍历和索引能力。

## 9. `Codable`

优点：

- 类型安全、自动合成、与值类型自然结合。

真实边界：

- 后端字段不稳定；
- 多态结构；
- 日期/数字精度；
- 缺失、`null`、默认值语义；
- 大 JSON 的峰值内存；
- 错误定位和兼容迁移。

建议把网络 DTO 与领域模型分开，通过显式映射做验证和版本兼容。

## 10. Property Wrapper、Result Builder 与 Macro

| 能力 | 解决什么 | 风险 |
| --- | --- | --- |
| Property Wrapper | 复用属性存储/访问逻辑 | 隐藏状态和线程语义 |
| Result Builder | 声明式构建结构 | 错误信息和控制流理解成本 |
| Macro | 编译期生成/变换代码 | 工具链、调试、构建性能和可读性 |

高级回答要强调：语法抽象应减少重复并保持可追踪，而不是把业务逻辑藏进魔法。

## 11. 所有权与非复制类型

现代 Swift 的所有权能力包括 borrowing、consuming 以及 `~Copyable` 等表达。面试时可说明：

- 大多数普通泛型仍隐式要求可复制；
- 抑制 `Copyable` 约束后，值可能只能被消费一次；
- 适合表达文件句柄、唯一资源或大值移动语义；
- 属于版本敏感能力，落地前要核对工具链、标准库和 Deployment 策略。

不要为了展示新语法，把普通模型强行设计成不可复制类型。

## 12. 与 Objective-C 互操作

- OC nullability 决定 Swift 导入为非 Optional、Optional 或隐式解包 Optional；
- OC lightweight generics 保留 Foundation 容器元素类型；
- Swift `struct`、泛型、某些 enum 和并发声明不能直接完整暴露给 OC；
- `@objc` 允许进入 OC Runtime 边界，`dynamic` 强制动态派发语义；
- 混编模块要明确异常/错误、集合、可空性、命名和线程合同。

## 13. 高频问题

### Q1：Struct 一定比 Class 快吗？

不一定。要看复制、COW、逃逸、泛型特化、引用共享和数据大小；先选正确语义，再测量。

### Q2：`some P` 和 `any P` 的区别？

实现方固定但隐藏的具体类型 vs 运行时可容纳任意符合类型；前者保留更多静态信息，后者支持异构和动态替换。

### Q3：为什么 String 不能直接用整数下标？

Swift String 按 Unicode 扩展字形簇建模，一个用户感知字符可能由多个标量组成，不能假设固定宽度。

### Q4：Protocol Extension 默认实现有什么坑？

区分协议要求与 extension-only 方法；静态类型、existential 和具体类型可能影响派发。

### Q5：`weak` 与 `unowned` 怎么选？

弱引用允许对象先释放并变成 Optional；无主引用依赖更强的生命周期不变量，访问已释放对象会失败。
