# iOS 系统基础：从进程启动到一帧显示

> 知识树定位：A1 App 进程与可执行文件、A2 生命周期与资源治理、A3 事件与 Run Loop、A4 图形与渲染、A5 系统边界。

## 1. 一条完整主线

一个 iOS App 的核心运行链可以概括为：

```text
用户/系统触发启动
→ 校验并装载 Mach-O 与依赖
→ dyld 完成映射、重定位和初始化
→ 进入 main / @main
→ UIApplication 建立事件循环
→ App/Scene 生命周期创建 UI
→ 主 Run Loop 接收事件
→ UIKit/SwiftUI 更新视图和图层
→ Core Animation 提交事务
→ Render Server / GPU 合成显示
```

面试时不要把这条链说成“系统调用 `main` 然后显示页面”就结束。高级回答要指出启动成本、状态恢复、主线程约束、渲染提交和可验证指标。

## 2. App 与 Scene 生命周期

### 2.1 App 级与 Scene 级职责

- `UIApplicationDelegate` 处理应用级启动、推送、后台事件、URL 打开等共享行为；
- iOS 13 以后，启用 Scene 的 UIKit App 使用 `UISceneDelegate` 处理每个 UI 实例的连接、前后台与断开；
- 一个 App 进程可以存在多个 Scene，不同 Scene 可以处于不同状态；
- SwiftUI 的 `App` / `Scene` DSL 是更高层声明，但底层仍要服从系统生命周期和资源约束。

### 2.2 常见状态

| 状态 | 含义 | 应做什么 |
| --- | --- | --- |
| unattached / disconnected | Scene 尚未连接或已断开 | 创建/清理 Scene 相关资源 |
| foreground inactive | 前台但暂不接收交互 | 暂停动画、输入和短期任务 |
| foreground active | 可见且可交互 | 恢复 UI、刷新必要数据 |
| background | UI 不可见，执行时间受限 | 保存状态、结束关键工作、释放资源 |
| suspended | 进程仍在内存但不执行代码 | 不能指望此时处理逻辑 |

### 2.3 高频误区

- **误区：进入后台一定会收到终止回调。** 系统可能直接杀死挂起进程，不能把关键保存工作留到终止回调。
- **误区：App 只有一个窗口和一个生命周期。** 多 Scene 场景下，UI 状态应按 Scene 隔离。
- **误区：后台任务可以无限运行。** 后台执行取决于具体系统能力、声明、调度和资源策略。

### 2.4 面试答案

> 我会把业务状态分成进程级、用户会话级和 Scene/UI 级。共享服务不应错误地绑定到某个 Scene；界面导航和临时输入不应放进全局单例。进入后台时保存可恢复状态并停止非必要工作，不能依赖终止回调兜底。

## 3. Run Loop

### 3.1 它解决什么问题

Run Loop 让线程在“有事件时工作、无事件时休眠”，避免持续空转。每个线程都有对应 Run Loop 对象，但只有实际运行它才会处理事件；主线程的 Run Loop 由应用框架启动。

Run Loop 主要监控：

- Source：输入源、端口、手工信号等；
- Timer：定时触发；
- Observer：观察 Run Loop 进入、休眠、唤醒、退出等阶段；
- Block：安排到指定 mode 的回调。

### 3.2 Mode

Mode 是一次 Run Loop 迭代处理哪些 Source/Timer/Observer 的集合。滚动列表时，主 Run Loop 可能运行在跟踪相关 mode；只加入默认 mode 的 Timer 可能暂时不触发。把对象加入 common modes 是将其关联到该 Run Loop 定义的多个常用 mode，而不是一个真实、独立运行的 mode。

### 3.3 Run Loop 与线程、队列

- Run Loop 是事件驱动循环；
- Thread 是执行上下文；
- Dispatch Queue 是任务调度抽象；
- `async` 不等于新线程；
- Swift `async/await` 的任务恢复也不承诺回到原线程，除非有 Actor 隔离等约束。

### 3.4 常见应用

- 主线程事件分发和界面更新；
- 常驻辅助线程处理端口或特定输入源；
- Timer 与延迟任务；
- Autorelease Pool 在事件循环边界的排空；
- 通过 Observer 观察主线程卡顿，但要避免把粗糙阈值直接当成线上结论。

## 4. 触摸、响应链与手势

简化流程：

```text
硬件事件
→ 系统事件服务
→ UIApplication
→ UIWindow
→ hitTest(_:with:)
→ 最合适的 UIView
→ UIResponder 响应链 / Gesture Recognizer
```

`hitTest` 通常从窗口向子视图递归，结合隐藏、透明度、交互开关和 `point(inside:with:)` 判断。命中测试决定初始目标；响应链决定未处理事件或 action 如何向上传递。手势识别器拥有自己的状态机，并能协调失败依赖、同时识别和触摸取消。

追问重点：

- 为什么超出父视图边界的子视图可能点不到；
- 手势冲突怎样使用 delegate 和失败依赖解决；
- `sendAction` 如何沿响应链查找 target；
- 不应通过无限扩大 hit area 掩盖布局错误。

## 5. 从视图变化到屏幕显示

### 5.1 UIKit

- `UIView` 管理布局、交互和高层绘制行为；
- `CALayer` 保存可参与合成的图层内容和几何属性；
- 属性变化通常在事务中收集，Run Loop 合适阶段提交；
- Render Server 和 GPU 负责后续合成；
- 主线程负责大部分 UIKit 状态变更，但最终显示并不是“主线程直接把每个像素画到屏幕”。

### 5.2 一帧可能在哪里慢

| 阶段 | 常见问题 |
| --- | --- |
| 事件与业务 | 主线程同步 I/O、锁等待、JSON/图片重活 |
| 状态与布局 | 更新过频、约束冲突、重复测量、大量视图创建 |
| Commit | 图层树过大、离屏渲染、内容上传 |
| Render | 复杂混合、过度绘制、大图、GPU 压力 |

### 5.3 帧率不是唯一指标

只报“平均 60 FPS”可能掩盖少量严重卡顿。更好的证据包括：

- hitch 时间和次数；
- hang 时长和主线程调用栈；
- 帧生命周期；
- 交互到下一帧的延迟；
- 对照设备、系统版本、数据规模和温度状态。

## 6. Auto Layout

Auto Layout 把视图关系转化为线性约束系统。一次布局问题至少要区分：

- 缺少约束导致位置/尺寸不确定；
- 冲突约束导致系统打破优先级较低的约束；
- intrinsic content size 提供内容驱动的宽高；
- content hugging 表示不希望被拉大；
- compression resistance 表示不希望被压小；
- `layoutIfNeeded()` 会在需要时立即完成布局，滥用会增加主线程成本。

面试表达：

> 我先写清楚水平和垂直两个轴上的自由度，再检查每个视图是否被充分约束。冲突时读取控制台的约束标识和视图层级，不通过随意降低优先级来“消除日志”。

## 7. 沙盒、资源与进程约束

典型容器用途：

- App Bundle：签名资源，只读；
- Documents：用户生成且需要长期保存的文件；
- Library/Application Support：应用管理的持久数据；
- Library/Caches：可重建缓存，系统可能清理；
- tmp：短期临时文件，不能当持久存储。

系统还会约束：

- 内存：过高可能收到 warning 或被 jetsam；
- CPU 与能耗：后台尤其严格；
- 磁盘：备份属性、缓存清理、数据保护；
- 隐私权限：目的字符串与最小化访问；
- 网络：ATS、后台传输、蜂窝策略。

## 8. 启动优化

### 8.1 分类

- 冷启动：进程不在内存，需要完整装载；
- 温启动：部分系统或文件缓存可复用；
- 热恢复：进程仍存活，从后台回前台。

### 8.2 原则

1. 先定义“用户可交互”的结束点；
2. 用 Organizer、Instruments、MetricKit/signpost 或测试指标分段；
3. 减少启动路径上的动态库、Objective-C 类注册、静态初始化和同步 I/O；
4. 把非首屏必要工作延后，但保证依赖顺序和失败可见；
5. 优化后用真实设备、Release 配置和重复样本验证。

### 8.3 错误做法

- 所有初始化都简单塞进后台队列；
- 为了数字好看提前显示不可用的空壳首屏；
- 只在模拟器测量；
- 把一次偶然结果当成结论；
- 用延迟执行制造竞态。

## 9. 高频问题与追问

### Q1：Run Loop 为什么能让线程休眠？

要点：事件源、内核等待、唤醒、一次迭代、mode 过滤；不要只背“死循环”。

追问：Timer 为什么在滚动时不触发？common modes 到底是什么？

### Q2：进入后台后一定会发生什么？

要点：生命周期通知、执行受限、保存与释放；不保证终止回调；具体后台能力取决于场景。

### Q3：UIView 与 CALayer 的区别？

要点：UIView 负责交互/布局和高层语义，CALayer 负责可合成内容与动画；二者协作而非互斥。

### Q4：怎样证明首屏优化有效？

要点：定义终点、分段埋点、真实设备 Release、多样本分布、回归门槛、不能牺牲可用性。

### Q5：列表滑动时为什么掉帧？

要点：按主线程、布局、图片、状态更新、提交和 GPU 分类；先用 Hitches/Time Profiler 证据定位。
