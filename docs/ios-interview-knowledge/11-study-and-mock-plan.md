# 学习、模拟面试与复盘计划

> 知识树定位：H3 职级能力、H4 面试表达、H5.6 复盘。所有练习使用 [00-knowledge-system-map.md](00-knowledge-system-map.md) 节点编号。

## 1. 先做诊断，不从第一页机械读

给每个 L2 节点标记：

| 状态 | 定义 |
| --- | --- |
| 0 未知 | 无法给出基本定义 |
| 1 知道 | 能说用途，机制不完整 |
| 2 可用 | 能解释并实现常规场景 |
| 3 熟练 | 能处理失败、性能和兼容 |
| 4 引领 | 能做跨层设计、验证和迁移 |

优先顺序：

```text
岗位关键且低分
→ 高频主链缺口
→ 真实项目无法证明的节点
→ 版本敏感补充
```

## 2. 诊断题

不查资料，每题 5 分钟口述：

1. A：从点击图标到首屏可交互发生什么；
2. B2：OC 消息找不到实现后的处理链；
3. B3：`some P`、`any P` 和泛型的区别；
4. C：搜索请求乱序覆盖怎样修；
5. D：SwiftUI 状态为什么会丢失；
6. E：弱网下写请求如何安全重试；
7. F：列表卡顿如何用工具定位；
8. G/H：设计离线图片 Feed 并说明验证。

每题检查：

- 是否先给结论；
- 是否有对象/状态/调用链；
- 是否有失败边界；
- 是否有验证；
- 是否超过 3 分钟仍没进入重点。

## 3. 30 天计划

每天额外用 20 分钟完成一个 A0 算法/基础检查点：

```text
复杂度 → Array/Hash → Stack/Queue → Tree/Heap → Graph
→ Binary Search/Window → DFS/BFS → DP
→ Process/Thread/VM → HTTP/TLS → Transaction/Index → Compile/Link
```

重点是写出不变量、复杂度和边界，不追求冷门竞赛技巧。

### Week 2

### Week 3

### Week 4

- UIKit/SwiftUI 混合页面；
- signpost + 性能测试；
- feature flag 切换新旧实现。

## 6. 项目故事库

准备至少六个故事：

| 故事 | 必须有 |
| --- | --- |
| 性能优化 | 基线、工具、根因、数字、回归 |
| 稳定性事故 | 影响、诊断、修复、预防 |
| 架构演进 | 原问题、方案比较、迁移、结果 |
| 跨团队协作 | 依赖、冲突、决策、交付 |
| 失败项目 | 自己的判断错误和修正 |
| 用户价值 | 技术选择如何改善业务或体验 |

使用结构：

```text
背景
→ 目标和约束
→ 我的职责
→ 证据和判断
→ 行动
→ 结果
→ 反事实：如果重来会怎样
```

避免只说“我们做了”。明确自己的决策、代码、验证和影响。

## 7. 模拟面试轮次

### Round A：基础机制，30 分钟

- B2 或 B3；
- C；
- A；
- 每题追到“为什么”。

### Round B：业务闭环，45 分钟

- D + E 场景；
- 强制覆盖取消、失败、缓存、安全；
- 最后用 F 验证。

### Round C：系统设计，60 分钟

- H2 任选；
- 先澄清；
- 画主链；
- 补失败；
- 做量化；
- 给迁移/发布。

### Round D：资深综合，90 分钟

- 项目深挖；
- 跨层故障；
- 架构演进；
- 组织协作；
- 反事实和长期风险。

每轮记录：

| 项目 | 评分 0～4 | 证据 |
| --- | --- | --- |
| 顶层定位 |  |  |
| 机制准确 |  |  |
| 边界完整 |  |  |
| 方案取舍 |  |  |
| 验证闭环 |  |  |
| 表达结构 |  |  |

只记录三个优先缺口：

1. 会影响岗位判断的核心错误；
2. 多次出现的结构问题；
3. 能在下一轮明确验证的改进。

不要把复盘变成几十条无法执行的 TODO。

## 10. 面试前检查

- 能在 2 分钟内介绍自己和最强项目；
- 能画出项目架构和数据流；
- 每个性能数字有测量方法；
- 每个“优化”有修复前后基线；
- 每个架构选择有未选方案；
- 准备一个失败和一个冲突故事；
- 知道哪些事实需要版本复核；
- 不泄露前公司机密；
- 准备向面试官询问产品、工程质量和团队协作的问题。

## 11. 完成标准

这套复习不是“文档全部看完”才完成。目标岗位的关键主链达到：

- 能从 L1 定位到 L3；
- L4 五项中至少完成解释、边界、设计和验证；
- 两轮模拟没有重复核心错误；
- 三个真实项目故事有可验证证据；
- 系统设计能在 45 分钟内闭合正常、失败、验证和演进路径。
