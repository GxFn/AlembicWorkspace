## 执行顺序

1. 固定源码、脚本、配置、文档、测试与 fixture 清单；运行现有 typecheck、lint、全量单元测试基线。
2. 逐文件审查并记录职责、消费方、缺陷、冗余判断与对应测试。优先核对真实运行入口、失败/取消/超时、权限和部分结果。
3. 每个确认缺陷先在实际边界添加或修订回归用例，记录预期失败，再做最小修复并验证同一用例通过。
4. 根据消费扫描整理内部接口、删除无消费私有逻辑、合并重复实现与测试准备代码。公开契约和独有行为覆盖必须保留；需要相邻修改的提议记录为边界问题。
5. 复核修改与用户目标，执行完整仓库验证，输出逐文件清单、问题处置、接口与测试精简证据及剩余风险。

## 验证含义

- Mock provider、临时目录与可控 fixture 用于验证 Agent 自身行为；不依赖真实 API key。
- 基线通过仅代表现有测试结论；缺陷由新回归用例先失败再通过证明。
- 测试精简须保留成功、失败、取消、超时、权限拒绝、部分结果和公开合同的有效断言。
- 未经执行的代码阅读、静态扫描与历史记录不计为本次测试通过。
