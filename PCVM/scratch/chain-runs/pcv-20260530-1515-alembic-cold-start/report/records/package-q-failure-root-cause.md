## Source Logic Findings

### 1. `knowledge.submit` Required Fields Are Not Provider-Visible Enough

Runtime validation in `AlembicAgent/src/tools/v2/router.ts` rejects missing action params from the action-specific schema:

- `knowledge.submit` requires `title`, `description`, `content`, `kind`, `trigger`, `whenClause`, `doClause`, and `reasoning`.
- Q's first submit had `description` but no `title`, so it was rejected with `Missing required param "title" for knowledge.submit`.

But the provider-visible tool schema is generated by `generateLightweightSchemas()` in `AlembicAgent/src/tools/v2/registry.ts` as only:

- `action`
- `params`

It does not expose the `knowledge.submit` required fields at the function-schema level. The Producer prompt mentions a title in prose, but the explicit `插件适配字段（每个 knowledge 提交必须附带）/ 必填（REQUIRED）` block still starts at `trigger`, `kind`, `doClause`, `dontClause`, `whenClause`, and `coreCode`; it does not list `title`.

This is a code/prompt contract mismatch, not an isolated Q accident. Package O raw artifacts already contained `Missing required param "title"` observations before Package P.

### 2. Producer Exit Logic Ignores Remaining Structured Findings

Producer strategy currently transitions from `PRODUCE` to `SUMMARIZE` when:

```ts
m.submitCount >= b.maxSubmits ||
(m.submitCount > 0 && m.roundsSinceSubmit >= b.idleRoundsToExit) ||
(m.consecutiveIdleRounds >= b.searchBudgetGrace && m.submitCount === 0)
```

Package Q had:

- `submitCount=1`
- three consecutive non-submit rounds after the accepted Recipe (`knowledge.detail`, `meta.tools`, `meta.tools`)
- `idleRoundsToExit=3`

So the transition to `SUMMARIZE` was deterministic once those non-submit actions happened. The tracker does not know the Producer has `6` structured Analyst findings and only `1` accepted Recipe, so it cannot protect the remaining `5` obligations.

This is a source-level responsibility gap: Producer completion is controlled by activity idleness, not by candidate obligation coverage.

### 3. Producer Tool Boundary Allows Round-Wasting Actions

The Producer prompt says to submit directly and use `meta({ action: "review" })` only for light self-check, but the actual provider-visible tools allow:

- `knowledge.detail`
- `meta.tools`
- `memory.recall`
- repeated `code.read`

Q spent four Producer iterations before the only successful candidate was accepted, then spent three more iterations on detail/tool-schema queries. This is not purely random: the current tool surface and `auto` tool choice permit those actions, and the state machine punishes the resulting non-submit rounds by entering `SUMMARIZE`.

### 4. Analyze Growth Is Secondary Here

Q analyze input grew from O's `187313` to `216300`, mainly because Analyze ran `19` iterations instead of O's lower analyze count. Q still preserved:

- `pcvAnalyzeGroundingInvalidNoEvidence=0`
- Analyze final Markdown single-source behavior
- Producer direct-code replay improvement

So Q's decisive failure is not Analyze quality or SourceRef. The first blocker is Producer conversion coverage.

## Next Repair Direction

Package R should be a source/unit repair before another AlembicTest live run:

1. Make `title` and all `knowledge.submit` required fields provider-visible in the Producer contract.
2. Restrict Producer non-submit actions:
   - prefer `knowledge.submit`;
   - disallow or strongly gate `knowledge.detail` and `meta.tools` during Producer;
   - keep `code.read` only for missing short snippets from Analyst-cited files.
3. Add Producer candidate-obligation tracking:
   - derive target submit count from structured Analyst findings;
   - do not enter `SUMMARIZE` only because of `roundsSinceSubmit` while `submitCount < targetStructuredFindings`;
   - after a rejected submit, inject a field-specific repair nudge before idle termination.
4. Add source/unit tests for the Q path:
   - missing-title submit contract is visible before submission;
   - one accepted submit + `detail/meta/meta` does not force SUMMARIZE when structured findings remain;
   - Producer final summary is allowed only after all structured finding obligations are covered or explicitly blocked by a real field/evidence reason.

Do not reopen SourceRef. Do not classify this as a metric-only failure. The next blocker is Producer completion coverage under the final LLM input/output efficiency objective.
